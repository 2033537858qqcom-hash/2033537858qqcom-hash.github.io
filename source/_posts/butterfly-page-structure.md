这个博客不是从零写一个完整系统，而是基于 Hexo 和 Butterfly 主题做定制。这样可以先把内容发布、页面结构、主题样式和自动部署跑通，再慢慢把音乐、番剧记录、右键菜单、点击特效这些个性化功能补上。

## 技术栈

- Hexo：负责把 Markdown、数据文件和静态资源生成最终网页。
- Butterfly：作为博客主题，提供首页、文章页、分类、标签、归档、侧边栏等基础结构。
- Markdown：用来写文章内容，文章都放在 `source/_posts/`。
- YAML：用来维护结构化数据，比如 `source/_data/anime.yml` 里的番剧条目。
- EJS/Hexo Script：用 `scripts/anime-page.js` 在构建时把番剧数据渲染成卡片。
- CSS：通过 `source/css/custom.css` 调整整体视觉、卡片、右键菜单、点击文字效果和响应式表现。
- JavaScript：实现音乐播放器、主题切换补充、右键菜单、点击社会主义核心价值观词语等交互。
- APlayer：用于左下角固定音乐播放器。
- GitHub Pages：托管最终生成的静态网站。
- GitHub Actions：每次推送后自动执行安装依赖、构建和部署。

## 搭建思路

第一步先保证博客能正常生成和访问。项目的核心命令是 `npm run build`，它会执行 `hexo generate`，把 `source/` 里的内容生成到 `public/`。

第二步把部署流程自动化。仓库里已经加入 `.github/workflows/pages.yml`，推送到 `main` 后，GitHub 会自动运行构建并发布到 GitHub Pages。这样以后更新文章或配置时，只需要提交并推送，不需要手动上传静态文件。

第三步做主题定制。没有直接修改主题源码，而是通过 Butterfly 的 `inject` 配置引入自定义 CSS 和 JS。这样后续主题升级或依赖重装时，自定义功能不容易丢。

第四步把适合长期维护的内容改成数据驱动。例如番剧页不再手写表格，而是维护 `source/_data/anime.yml`。页面展示交给构建脚本生成，后面新增番剧只需要复制一段 YAML 数据。

## 页面结构

当前主要内容分成几类：

- 文章页：放技术笔记、搭建记录和设计想法。
- 番剧页：通过数据文件维护条目，再渲染成卡片。
- 音乐页：配合左下角播放器，展示和播放本地音乐文件。
- 随笔页：用于轻量记录日常想法。
- 友链和留言页：作为后续社交入口。

这些页面先保持轻量，等内容多了以后再继续拆分更复杂的功能。

## 个性化功能

博客目前已经加入了一些个人化细节：

- 昼夜背景：白天和夜晚使用不同背景图，让主题切换更有氛围。
- 音乐播放器：使用本地 MP3 文件和本地封面图，减少外链失效问题。
- 自定义右键菜单：替代浏览器默认右键，让操作和视觉更统一。
- 点击文字特效：点击页面时依次显示社会主义核心价值观词语。
- 数据驱动番剧卡片：用 YAML 管理番剧信息和封面。

## 后续方向

后面可以继续优化三件事。

第一是内容质量。博客最重要的还是文章本身，可以逐步补充真实的学习记录、项目踩坑和日常复盘。

第二是资源管理。图片、音乐和封面最好都放在 `source/img/`、`source/music-files/` 这类固定目录里，并使用英文文件名，避免线上路径编码问题。

第三是页面体验。现在的功能已经能用，后续可以继续打磨移动端布局、图片压缩、加载速度和文章封面的一致性。

整体思路就是：先让博客稳定上线，再把常用内容变成容易维护的数据，最后慢慢补视觉和交互细节。
